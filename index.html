Dorking For Bug Bounty

A working reference of Google, Shodan, and GitHub search queries for recon during authorized penetration tests and bug bounty engagements.

  1. 1 Enter your target domain
  2. 2 Filter or browse dorks
  3. 3 Run them with one click
For research and education only. Only use these dorks on your own systems, or on public bug bounty platforms (HackerOne, Bugcrowd, Intigriti, etc.) and only within that program's published scope and rules. Enter your target's domain above, hit Apply, then use each row's search button to open that dork already filled in on the right engine.

Login & admin panels

Surface exposed authentication and management interfaces.

inurl:admin intitle:login
Generic admin login pages indexed by Google.
inurl:/wp-admin/ -inurl:wp-content
WordPress admin dashboards, excluding static asset paths.
intitle:"cPanel" inurl:2083
Hosting control panel logins on the default cPanel port.
inurl:/phpmyadmin/ intitle:"phpMyAdmin"
Publicly reachable phpMyAdmin instances.
intitle:"Router Login" inurl:setup.cgi
Consumer router admin panels left internet-facing.

Config & environment files

Files that often leak credentials or connection strings.

filetype:env "DB_PASSWORD"
.env files with database credentials indexed directly.
filetype:yml "database:" "password:"
YAML configs (Rails, Symfony, CI) with inline DB passwords.
filetype:xml "connectionString"
.NET web.config files exposing connection strings.
filetype:ini "password" -git
Application .ini files with plaintext credentials.
filetype:conf "define('DB_PASSWORD'"
wp-config-style constants leaked in .conf files.

Backups & database dumps

Archived or exported data left in web-accessible paths.

filetype:sql "INSERT INTO" "password"
SQL dumps containing user tables with password columns.
intitle:"index of" "backup.tar.gz"
Open directory listings serving compressed backups.
filetype:sql intext:"phpMyAdmin SQL Dump"
Raw database exports generated via phpMyAdmin.
inurl:backup filetype:zip
Zipped backup archives sitting in public URLs.
intitle:"index of" "db.sqlite3"
Exposed SQLite database files (common in Django/Flask apps).

Sensitive documents

Internal files not meant for public access.

site:{domain} filetype:pdf "confidential"
Internal PDFs marked confidential, scoped to a target domain.
filetype:xls intext:"username" intext:"password"
Spreadsheets storing plaintext credential lists.
filetype:doc "internal use only"
Internal-only Word documents that leaked into the index.
intitle:"index of" "id_rsa"
Directory listings exposing private SSH keys.
filetype:log intext:"password"
Application logs that recorded credentials in plaintext.

Cloud storage & keys

Buckets and paste sites that reveal object storage or secrets.

site:s3.amazonaws.com "{domain}"
S3 buckets referencing a target's name.
inurl:storage.googleapis.com "{domain}"
Google Cloud Storage objects tied to a target.
intext:"api_key" filetype:json
JSON config or credential files with API keys.
site:pastebin.com "{domain}" "password"
Pastebin leaks mentioning a target domain and credentials.
intext:"AKIA" filetype:env
AWS access key prefixes leaked inside .env files.

Error messages & stack traces

Verbose errors that reveal stack, paths, or query structure.

intext:"Warning: mysql_connect()"
Unhandled MySQL connection errors printed to the page.
site:{domain} "SQL syntax" "MySQL"
Pages leaking raw SQL error output, useful for injection recon.
intitle:"index of" "error_log"
Open directories serving Apache/PHP error logs.
site:{domain} intext:"stack trace" intext:"at line"
Application stack traces exposed on a target's own pages.
intext:"Fatal error" filetype:log
PHP fatal error logs left publicly indexable.

Legacy & vulnerable banners

Software versions with known, publicly documented issues.

Apache builds matching a specific, older version string.

SSH daemons running an older, fingerprintable version.
"IIS/6.0"
Legacy IIS 6.0 banners, long past end of support.
title:"Apache Tomcat" intitle:"Manager"
Tomcat manager consoles, a common misconfiguration target.

API keys & tokens

Provider-specific secret formats committed by accident.

AWS access key ID prefix inside committed .env files.
"aws_secret_access_key" -example
Real AWS secret keys, filtering out obvious placeholder repos.

Hardcoded bearer tokens left in environment files.
"client_secret" extension:json
OAuth client secrets committed in JSON configs.
"xoxb-" "slack"
Slack bot tokens matching the xoxb- prefix.

SQL files with plaintext password columns.

Sensitive filenames

File paths that are almost never meant to be public.

Private SSH keys committed under their default filename.

PEM-encoded private keys anywhere in a repo.

Company-specific recon

Narrow a search down to one organization or domain.

Env files across every repo under a GitHub organization.

API key references scoped to a specific GitHub user or org.

Internal-facing READMEs that reference the target domain.
"{domain}" extension:log
Committed log files that mention the target domain.
